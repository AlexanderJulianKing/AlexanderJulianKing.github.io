Daily News-Podcast Pipeline

An automated news program that agentically researches the day's news, writes an anchor-and-reporter script, fact-checks the script against the sources it gathered and auto-corrects source-grounded errors, then ships an audio and video episode to YouTube.

1. The pipeline

Six stages run top to bottom each morning. Each one skips itself if its output already exists, so the run is resilient to LLM-provider hiccups: a retry resumes where it left off instead of redoing finished work.

1
Gatherdeep-dive below ↓

Scrape NPR, AP, Democracy Now, ProPublica, CalMatters, Drop Site News, City of Riverside → research the headlines and pick 2 to cover in depth and 5 to cover briefly → dig into the two deep-dive picks with an adaptive agent backed by cross-day memory (what past episodes already covered) → dedupe against the last 7 days.

produces → vetted story summaries · research notes · saved source excerpts (raw fetched article text, kept for fact-checking) · a cross-day memory store
2
Write scripts

Each episode is two parts: a 5-story overview the anchor reads solo (written by Gemma from the five stories’ short web briefs), and two in-depth segments told as dialogue between one anchor and two reporters (written by Opus). Plus the episode title.

3
Fact-finder gate

A fact-check of the finished script (the overview and both segments) before any audio is made: three passes (detailed below), then an editor that corrects the factual errors the sources contradict.

4
Generate audio

Cloud text-to-speech, a distinct voice for the anchor and each reporter, with intro music mixed in and assembled into the full episode.

5
Video

Combines the audio with the cover image into the final video file.

6
Upload

Uploaded to YouTube and published public, with the generated episode title.

2. Inside the pipeline, step by step

Start to finish: how the day's stories get picked, researched in depth, fact-checked, and corrected before they're voiced. Every box says what it does and who does it: plain program code, Google's search, a database, or an AI model (an LLM, like ChatGPT, but called from code; the model is named).

1. Story selection · headlines → the day's picks

Headlines come from 7 sites: NPR, AP, Democracy Now, ProPublica, CalMatters, Drop Site News, and City of Riverside (local-government notices). Most are read by Gemini with web grounding, two (CalMatters, Drop Site) by direct scrapers. Then a two-tier funnel narrows them: Tier 1 scores every headline and keeps the top ~10, then Tier 2 web-researches those and makes the final picks.

2. Gather · one story → in-depth summary

This runs for each of the two deep-dive picks, then saves the results and indexes them.

"Usable" means an article whose headline read as relevant, downloaded, and summarized cleanly. It keeps up to 3. The search escalates on an empty result: last 1 day → last 3 days → a reworded query. If all three fail, the story is dropped: the episode just airs one fewer deep-dive segment, never dead air. The grounded overview that follows doesn't reuse that article; it takes the story and runs its own search.

3. Grounded search · answers only from verified sources

"Grounded" means tied to real fetched sources, never the model's own memory. Both the first pass and the research agent's source-checking tool (the "source hunter") use this: it answers only from verified excerpts, or reports no evidence. It never guesses.

The whole flow runs once with a standard model and, if that comes up short, retries once with a stronger one. Every run is logged, and those saved excerpts become what the fact-finder later checks against.

4. Research agent · the dig-deeper loop

It starts from the story's research so far, the article summaries plus the grounded search's first findings, then the orchestrator (Opus) keeps deciding "dig more or stop," calling two tools, until a second model (GPT-5.5), acting as an adversary that tries to poke holes in the findings, signs off. Up to ~5 rounds; it stops after 2 rounds that turn up nothing new.

One tool is the source hunter (workflow 3), which answers only from verified sources; the other runs a fresh web search and pulls in another relevant article. The adversary checks once: if it spots a gap, it forces one more dig; otherwise the agent hands its findings back to Gather.

5. Cross-day memory · what past episodes already covered

So the system remembers what past episodes covered. Each note is turned into a vector (a list of numbers that captures its meaning) and stored; a new story's question becomes a vector too, and the most similar past notes come back. Written each day (left), read per story (right).

The memory gives the system continuity (build on a running story), avoids repeating what it already covered, and nudges toward fresh angles; notes are tagged by storyline. If nothing matches, it simply starts fresh.

6. The fact-finder · the last check before voicing

One last fact-check before the episode is voiced and published. Every script is checked against the real source text the pipeline fetched (the saved excerpts), not the LLM summaries, which would carry any invented claim straight through. Three passes, each matched to a different way fabrication slips in: a quote check (are quoted words verbatim?), a faithfulness check (does every claim match its source?), and a stable-fact check (are names and titles right?).

Runs on every script (overview + segments) just before text-to-speech.

Pass 2 runs on the strong model (GLM) against only that segment's sources: the tight context is what lets it catch a subtle contradiction a long, noisy corpus would drown. In the 2026-06-23 episode it flags the script's “a crushing defeat in the Makerfield by-election” when the sources say Andy Burnham won it with 55%, a victory, not a defeat (a reversal, pass 2). Only the source-grounded flags (from passes 1 and 2) go to the editor (workflow 7). The stable-fact pass stays advisory: its web check is unreliable on facts newer than the model's training. In the same episode it wrongly insisted the Fed chair was still Powell, dismissing the 2026 dates as “simulated”, so it's logged but never auto-edited. Every flag is logged; it never blocks the run.

7. The fact-finder editor · fix the confirmed errors before voicing

Runs only on scripts with a source-grounded flag (quote or faithfulness). Opus proposes verbatim find/replace fixes for the confirmed factual errors; a GPT-5.5 adversary signs off on each; then plain code applies it, but only where the exact phrase occurs once. Up to 3 rounds.

The reference it checks against is that segment's fetched excerpts. The adversary rejects anything uncertain or unsupported, so only checkable, contradicted facts change; ambiguous spans and everything else stay logged flags.
